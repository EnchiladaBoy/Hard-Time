WINDOWS x64 PORT NOTES

Source correspondence
  The original NSIS installer is extracted without executing it. The archived
  BASIC files remain pinned to the existing repository revision. All 233
  named game functions match recovered symbols from the supplied windowed
  executable. This is source-assisted reconstruction, not a byte-identical
  decompilation or an authenticated upstream source release.

Build
  The Windows patch follows the shared Linux/native corrections and is only
  applied for windows-x64. It selects the published Windows LLVM 19.1.5 SDK,
  uses MSVC/Windows SDK library paths from the chosen developer environment,
  resolves DIA SDK libraries, and builds command-line tools without MFC,
  TiltFive or FMOD. OpenAL Soft supplies the audio backend. COFF linking uses
  the Windows GUI subsystem and embeds the native manifest.

Runtime
  The shared deterministic timer now runs on Windows, retaining missed ticks.
  Windows fonts use original Comic Sans MS and standard Arial/Consolas/Times
  New Roman families; bold/italic flags participate in native font selection
  and font cache keys. Round-to-even helpers supply LLVM's missing CRT calls.
  Errors also reach stderr for launcher logs.

  The presented backbuffer is preserved in an OpenGL renderbuffer before a
  WGL swap and restored afterwards. It never depends on reading an occluded
  desktop front buffer. Allocation follows drawable size and resources are
  released with the SDL context. This supports legacy post-Flip photographs
  and repeated F12 captures.

  Legacy texture alpha/mask flags produce grayscale alpha for source images
  without an alpha channel, preserve explicit RGBA alpha, and whiten the
  alpha-only texture's color. This fixes square shadows. Ordinary 2D images
  keep their own masking rules.

Save and shutdown
  AppCloseEvents enables opt-in close handling. AppCloseRequested remains
  set after SDL_QUIT, letting the game unwind its screen loop through normal
  save/cleanup code before End. Other programs retain immediate close unless
  they opt in. Alt+X follows the same cleanup route in this game.
  Slot names are persisted after saving gameplay. Screenshot images are
  released after saving. The launcher backs up Data and excludes concurrent
  launches/updates. The on-disk int32/float32/string format is unchanged.

Display refresh
  PollTimer consumes elapsed ticks without blocking and pumps input even on
  frames with zero ticks. TimerTween returns the fraction sampled by the last
  poll/wait. Both operations share WaitTimer's monotonic cumulative clock.
  Gameplay captures the world before each fixed 30 Hz update and interpolates
  camera, entity and skeletal transforms when drawing intermediate frames.
  Interpolation displays the previous/current tick pair, adding up to one
  simulation tick of visual delay. Simulation transforms remain unchanged.

  Extra HUD draws restore the RNG state and reuse the last HUD seed; expression
  resets still run only on simulation frames. Dialogue rendering also mutates
  gameplay state, so scripted conversations, menus, loading and pause retain
  their original cadence. Separating those side effects is future work.

  Swap interval selection is cached per graphics context and changes only
  when Flip's wait argument changes. Unsupported adaptive vsync falls back to
  ordinary vsync. If neither works, a monotonic limiter follows the current
  display, with a 60 Hz fallback for unspecified rates (0 or 1 on Windows).
  Deadlines retain their phase so sleep overshoot does not accumulate.
  Flip 0 remains immediate. Hardware vsync pacing is not replaced by a sleep.

Rewrite feasibility
  All 18 archived BASIC files and the C++ engine are available. The current
  compiler already emits native x64 machine code through LLVM. A language
  change alone does not remove the fixed update loop or improve GPU access.
  An incremental C++ port can retain the engine, assets and serialization
  while replacing game systems with typed data and explicit update/render
  boundaries. C# is also possible, with additional engine integration or an
  engine migration. Either requires behavior and save compatibility checks,
  especially for legacy numeric conversions, AI, animation and dialogue.

  A complete Ghidra decompilation is not a prerequisite. Source-assisted
  comparisons already matched all 233 named functions. Targeted disassembly
  remains useful for discrepancies between the archived source and original
  executable; symbol correspondence alone does not prove identical behavior.

Limitations
  Focused testing is recorded in provenance/windows-validation.json.
  This does not establish a complete playthrough or compatibility with every
  GPU, audio device, controller, display scaling mode or Windows release.
